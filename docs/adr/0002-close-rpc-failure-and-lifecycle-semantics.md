# ADR-0002：闭合 RPC 失败语义与资源生命周期

- 状态：Accepted
- 日期：2026-07-19
- 决策者：threetwoa

## 背景

当前调用链已经覆盖动态代理、服务发现、负载均衡、重试、TCP 编解码与反射调用，但失败无法稳定返回调用方：

- TCP 连接或解码失败可能使 `CompletableFuture` 永久等待。
- 服务端反射异常仍使用成功状态返回，客户端也不检查远端异常。
- `requestId` 只在协议头中回写，没有校验响应是否属于当前请求。
- 注册中心缓存失效、Spring Bean 生命周期和部分治理策略仍存在未完成语义。

这些问题横跨协议、公共 API、注册中心和 Spring 集成，必须作为一个分阶段兼容变更处理。

## 决策

1. 保持现有 17 字节协议头布局不变，继续使用 `status` 和 `requestId` 字段表达结果状态与请求归属。
2. 客户端为连接和响应设置有界超时。连接、写入、解码、关闭和响应超时必须完成或异常完成 Future，不允许无限等待。
3. 服务端调用失败时返回非 OK 状态和可序列化错误信息；客户端将其转换为统一的 `RpcException`，再交给重试与容错层。
4. 短期保留“一连接一请求”模型，但客户端必须校验响应 `requestId`。连接复用与多路复用留作后续独立 ADR。
5. 注册中心缓存统一按 `serviceKey` 隔离和失效。监听服务前缀而不是仅监听首次发现的节点。
6. Spring Provider 注册实际 Bean 实例，不再由传输层每次反射创建实现类。
7. 未完成的 fail-over 与 fail-back 不再返回 `null`。在缺少完整调用上下文前，明确失败并保留扩展接口。
8. 新增根聚合 POM 与确定性依赖版本，按依赖顺序统一构建八个模块。

## 兼容策略

- 不改变服务接口、SPI 文件名和现有 SPI key。
- 不改变协议魔数、版本和消息头长度。
- `LocalRegistry` 对外保留按类型注册入口，同时增加按实例注册能力。
- 新增配置项提供默认值，现有 `application.properties` 可继续运行。

## 验证

1. 协议编解码覆盖非法版本、非法长度、远端异常和 requestId 不匹配。
2. TCP 客户端覆盖连接失败与响应超时，断言调用在限定时间内结束。
3. 注册中心缓存覆盖多服务隔离、PUT/DELETE 失效和空结果刷新。
4. Spring 集成覆盖 Bean 实例复用和代理字段注入。
5. 根目录执行 Maven 全量构建，并单独标记依赖 Etcd/ZooKeeper 的集成测试。

## 后果

调用失败会从“挂起或返回 null”变为明确异常，可能暴露此前被静默吞掉的业务错误。资源和缓存生命周期更可预测，但实现复杂度会上升；连接池、多路复用、认证与跨语言协议仍不在本次范围内。
